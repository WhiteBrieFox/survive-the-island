# 技术方案

## 1. 目标

- 2 至 5 人通过浏览器实时联机。
- 房主在本机启动一个服务，监听 `0.0.0.0:<PORT>`；朋友通过 `http://公网或局域网IP:端口` 进入。
- 同一个 Node.js 进程同时提供网页、WebSocket 和房间服务，端口映射只需开放一个 TCP 端口。
- 桌面浏览器优先，平板可用；手机首版支持观战和基础操作，不为小屏牺牲主桌体验。
- 3D 是主要交互界面，不做“2D UI 加一个装饰性 3D 棋盘”。

## 2. 推荐技术栈

采用 TypeScript 单仓库：

| 层 | 选择 | 原因 |
| --- | --- | --- |
| 包管理与任务 | pnpm workspace | 前后端和共享规则包共用类型，安装快且锁定依赖 |
| 前端 | React + Vite | 开发反馈快，适合房间 UI、设置和覆盖层 |
| 3D | Three.js + React Three Fiber + Drei | 生态成熟，声明式管理棋盘、动画和后处理 |
| 动画 | React Spring / GSAP 二选一 | 棋子移动、沉岛、镜头和 UI 动画 |
| 状态 | Zustand | 管理客户端选择态、镜头、音量等非权威状态 |
| 服务端 | Node.js + Fastify + Socket.IO | 单端口提供静态文件、HTTP 健康检查和双向联机 |
| 规则核心 | 纯 TypeScript reducer/state machine | 可测试、可回放，不依赖渲染或网络 |
| 校验 | Zod | 校验环境变量、房间命令、存档和网络消息 |
| 测试 | Vitest + Playwright | 规则单测、协议集成测试和多浏览器端到端测试 |
| 持久化 | 首版 JSON 快照，后续可换 SQLite | 私人联机足够轻，异常退出后仍能恢复房间 |

首版不引入物理引擎。棋盘交互是离散六边格规则，使用物理会增加同步和穿模成本；海浪、漂浮和碰撞感用 shader 与动画表现。

```text
  ui/                  通用 UI 与主题
  assets/              资产清单、加载器和生成元数据
tests/
  e2e/                 多玩家浏览器测试

```

## 4. 联机架构

### 服务器权威

客户端发送命令，例如：

```ts
{ type: "MOVE_ADVENTURER", pieceId, path, expectedRevision }
```

服务器验证玩家身份、回合、阶段、行动点、路径和目标，再生成事件：

```ts
{ type: "ADVENTURER_MOVED", pieceId, path, revision, serverTime }
```

客户端不直接修改权威棋局，只播放已确认事件。这能避免不同步、重复点击和浏览器控制台直接作弊。

### 房间流程

1. 首页输入昵称，可创建或加入房间。
2. 创建者获得 6 位房间码和可选房间密码。
3. 加入者可选择入座或观战；观战者不占玩家名额，只接收公开信息。
4. 房主可以添加或移除 AI 玩家，AI 与真人共用 2 至 5 个玩家名额。
5. 玩家选择座位颜色并准备，2 人局自动分配双颜色。
6. 房主开始后锁定座位，进入探险者放置阶段。
7. 掉线玩家保留座位，使用本地重连令牌恢复。
8. 房主浏览器退出不销毁房间；只要本机服务仍运行，游戏继续。

### 观战与 AI

- 观战者不可提交棋局命令，也看不到地形背面、能力牌和探险者价值。
- 中途加入默认只能观战，避免改变既有座位与隐藏信息。
- AI 只运行在服务端，通过与真人相同的命令验证入口行动。
- 首版提供一个节奏较快的启发式 AI：优先救援高预期价值探险者、避免已知危险、争夺可控木筏，并在可获利时操纵生物。
- AI 思考采用短延时分步播放，观战者和真人能看清其行动，不瞬间跳完整个回合。

### 同步与恢复

- 每次状态变化递增 `revision`。
- 正常同步发送事件和该玩家可见的私有数据。
- 版本不一致或重连时发送按玩家裁剪后的完整快照。
- 每个已确认命令写入追加事件日志；阶段切换时写快照。
- 随机数使用服务器 seed 和可复现 PRNG，便于复盘与定位问题。
- 隐藏信息通过按玩家生成视图模型隔离，不把秘密数据广播后再靠前端隐藏。

## 5. 网络与部署

开发模式：

```bash
pnpm dev --host 0.0.0.0
```

正式本地服务：

```bash
PORT=4173 pnpm start
```

构建后由 Fastify 在同一端口提供静态网页和 Socket.IO。使用者需要：

- 允许系统防火墙接收入站连接。
- 局域网游玩时分享本机局域网 IP。
- 跨互联网游玩时在路由器配置 TCP 端口映射，或使用现有穿透工具。
- 若直接暴露公网，启用房间密码、连接频率限制和请求体上限。

纯 IP + 端口通常只能使用 HTTP。浏览器麦克风、部分剪贴板 API 等要求 HTTPS，因此首版不内置语音聊天，建议玩家同时使用现成语音工具。游戏、WebSocket 和音频播放本身可在 HTTP 下工作；BGM 需首次点击后才能播放，这是浏览器自动播放策略所致。

## 6. 3D 表现方案

视觉方向建议为“明亮的手工微缩景观 + 灾难电影式动态”，避免直接复制原作插画。

- 六边形岛屿有海滩、森林、山地三种高度与轮廓，随机铺设仍保持整体岛屿感。
- 水面使用轻量 shader：法线扰动、浅海颜色、泡沫边缘和低成本反射。
- 地形沉没分三段：震动、裂缝/下沉、浪花吞没；同时确保结算信息清晰。
- 棋子使用原创低多边形探险者，颜色与轮廓双重区分，照顾色觉差异。
- 生物入场和攻击使用短镜头强调，但可在设置中调低镜头运动。
- 合法格通过地面环、高度和鼠标指针共同提示，不只依赖颜色。
- 默认斜俯视自由旋转镜头，提供“一键回正”和跟随当前事件。

性能预算：

- 桌面目标 60 FPS，集显最低 30 FPS。
- 首屏压缩资源建议不超过 20 MB，完整资源按需加载。
- 模型统一使用 GLB；纹理优先 KTX2；重复树木、浪花和棋子使用实例化。
- 阴影限制在关键单位，远景使用烘焙光照或 blob shadow。
- 提供低/中/高画质档和关闭后处理选项。

## 7. 交互与可访问性

- 鼠标悬停预览合法性，点击选择，二次点击确认高风险动作。
- 移动路径显示行动点消耗；剩余行动点固定显示。
- 回合阶段、当前玩家和待响应事件始终可见。
- 所有 3D 操作都有键盘可达的棋子/格子列表作为替代入口。
- 支持色觉友好纹样、字幕式音效提示、独立 BGM/音效音量和减少动态效果。
- 不提供游戏内文字聊天首版，降低公网暴露后的审核与安全负担。

## 8. 测试策略

规则测试优先覆盖：

- 三类地势移除顺序。
- 每种生物的移动、停止与交互。
- 木筏控制权并列、超员登筏和木筏库存耗尽。
- 游泳每人每回合一次的限制。
- 漩涡、火山、驱逐剂和多个生物同格。
- 第三座火山与“无人待救”两类结束条件。
- 2 人双颜色和 5 人额外放置规则。
- 每位玩家不同的隐藏信息视图。

端到端测试启动 2 至 5 个浏览器上下文，覆盖建房、准备、完整回合、断线重连、刷新恢复和游戏结束。

## 9. 实施里程碑

1. **规则核心**：六边格数据、完整状态机、100% 牌面效果、规则单测。
2. **联机竖切**：建房、加入、放置、一个完整回合、断线重连。
3. **完整可玩**：全流程、计分、恢复、设置与基础音效。
4. **3D 视觉升级**：原创地形、生物、探险者、沉岛和攻击演出。
5. **资产与音频定稿**：AI 草图/模型/音乐生成，人工清理与压缩。
6. **稳定性**：多浏览器 E2E、弱网、性能档、部署说明。

先做低模灰盒但保持真正的 3D 操作，规则稳定后再替换高质量资产，避免美术返工。

## 10. 主要风险

- **版权风险**：公开发布前必须改为原创名称、图形、角色和声音；商业用途需法律确认。
- **端口映射风险**：部分运营商使用 CGNAT，路由器映射可能无效；届时需要内网穿透或小型云服务器。
- **隐藏信息风险**：网页玩家可截图记忆，这是线上化无法杜绝的行为，不应设计侵入式反作弊。
- **AI 资产一致性**：生成模型通常需要 Blender 清理拓扑、统一比例、UV 和动画骨骼，不能直接批量投入游戏。
- **公网安全**：服务端必须做输入校验、限流和依赖审计，绝不信任客户端。
