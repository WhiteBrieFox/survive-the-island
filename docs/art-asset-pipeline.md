# 3D 美术资产生产与接入规范

当前棋盘中的人物、生物、树木和木筏由 Three.js 基础几何体拼成，只适合作为玩法占位。正式效果要提升，不能只换一张贴图，而要将这些占位组件替换为统一风格的 GLB 模型、PBR 材质与轻量动画。

## 目标风格

- 明亮、欢快的热带冒险，危险感来自造型和动作，不使用阴暗恐怖滤镜。
- 高品质手工树脂桌游模型质感，轮廓略夸张，缩小后仍能看清角色和生物种类。
- 人物、生物、植被、地形共享同一套色板、材质粗糙度和光照基准。
- 保留棋盘可读性，不追求写实照片感；模型细节服务于俯视三分之四镜头。

## 生产流程

1. 在指定 Mira 会话生成风格圣经和正交多视图概念板。
2. 使用图生 3D 工具生成基础模型，或在 Blender 中按概念板建模。
3. 在 Blender 中清理拓扑、法线、穿插和薄片结构，统一模型朝向、原点与世界尺寸。
4. UV 展开并烘焙 Base Color、Normal、Roughness、AO；不把灯光和阴影烘进 Base Color。
5. 生物制作简短循环动画：待机、游动和攻击；人物制作待机、步行、游泳和乘筏姿态。
6. 制作 LOD0 与 LOD1，检查俯视镜头下的轮廓和玩家颜色识别。
7. 导出 GLB，使用 Meshopt 或 Draco 压缩网格，纹理使用 KTX2；保留未压缩源文件用于迭代。
8. 使用 Drei `useGLTF` 加载，当前程序化模型只作为加载失败时的降级显示。

## 资产预算

| 资产 | LOD0 三角面 | LOD1 三角面 | 纹理 | 动画 |
| --- | ---: | ---: | ---: | --- |
| 探险者 | 3k-6k | 1.2k-2.5k | 512 | 待机、步行、游泳 |
| 鲨鱼 | 4k-8k | 1.8k-3.5k | 512-1024 | 待机、游动、扑击 |
| 海蛇/巨兽 | 6k-12k | 2.5k-5k | 1024 | 待机、游动、攻击 |
| 树木单株 | 1.5k-3k | 600-1.2k | 512 图集 | 轻微摆动 |
| 木筏 | 2k-4k | 800-1.8k | 512 | 漂浮 |
| 地形模块 | 3k-8k | 1.2k-3k | 1024 图集 | 无 |

单个 GLB 尽量控制在 1.5 MB 内，首屏核心模型合计控制在 8 MB 内。树木、岩石等重复物使用实例化渲染，不为每个格子重复加载模型。

## 模型约定

- 单位：1 米；Y 轴向上，模型正面朝 +Z。
- 原点：人物位于双脚中心，生物位于水线中心，树木位于树干底部中心。
- 命名：`explorer`, `shark`, `sea_serpent`, `kaiju`, `raft`, `tree_palm_a`。
- 玩家颜色使用独立可替换材质槽 `PlayerColor`，不要为五种颜色复制五套网格。
- 碰撞和点击使用简单代理几何体，不直接对高模做射线检测。
- 阴影使用简化网格；小型远景资产关闭投射阴影。

## 运行时接入顺序

1. 先替换探险者、鲨鱼和棕榈树，这三类对粗糙感影响最大。
2. 再替换海蛇、巨兽、木筏和救援岛。
3. 最后升级六边地形、沉没动画、海浪、水花和火山特效。
4. 每批资产在桌面和手机实机检查帧率、显存、加载时间、点击区域与缩放可读性。

验收标准不是“模型单独看起来很精细”，而是棋盘全景下能快速分辨、近景不穿模、风格统一，并在普通手机浏览器保持稳定帧率。
